# ShipThenSell

作ったサービスを、必要としている人に届けるために。

Codexで見込み客を調べ、営業文面を用意し、届いた返信に対応するOSSです。
開発に集中していると、営業は後回しになりがちです。良いサービスが知られない
まま埋もれる状況を変えたい。そのために、日々の営業手順を公開します。

[English](README.md) / [セットアップ詳細](docs/setup.md)

## はじめ方

```sh
git clone https://github.com/yoshi0703/shipthensell.git
```

Codexデスクトップでこのフォルダをプロジェクトとして開き、次のように依頼します。

> ShipThenSellを私のサービス用にセットアップしてください。不足する情報を聞き、
> CRMとメールボックスの接続を確認して、このプロジェクトに3本のスケジュールを登録してください。

商品情報、営業対象、送信者、接続先、タイムゾーンを設定すると、Codexが3本を登録します。
cloneしただけでは登録されません。個人設定はGit管理外のフォルダに保存します。

| 初期スケジュール | 処理 |
| --- | --- |
| 毎日03:00 | 候補調査、公式フォームの確認、文面作成、CRM保存 |
| 毎日10:00 | 送信先と全文をまとめて提示し、承認後にフォーム送信 |
| 3時間ごと | 返信の分類、回答の下書き、空き時間の提案 |

調査は3並列で2波、各タスク最大50候補です。300件は調査上限で、送信数ではありません。
送信は各担当50試行、全体150試行を初期上限とし、時刻と件数は変更できます。
返信は下書きを初期値とし、利用者が明示的に選べば、前向きな返信、質問、日程調整への
回答を品質確認後に自動送信します。予定の登録や招待送信は行いません。

## 初版の範囲

Codex向けの手順、導入スキル、CRM定義、設定検証とハッシュ生成のPythonツール、
オフラインテストを含みます。実際の調査や送信は、利用者のCodexと接続サービスで
実行します。各利用者の環境でのスケジュール起動や外部送信は別途確認が必要です。
CRMは1台のホスト、1組のスケジュールで運用します。

営業禁止のフォームや配信停止の相手には送りません。CAPTCHA、ブラウザの確認、
本人が行う必要のある同意は回避せず停止します。送信結果が不明なら自動再送しません。
最初のフォーム営業は、対象と文面を確認した利用者の承認が必要です。

必要な環境はCodexデスクトップ、Google Drive/Sheets、Gmail、Google Calendar、
Codex内ブラウザ、Python 3.11以上です。利用可否と料金は各サービスの契約に依存します。
